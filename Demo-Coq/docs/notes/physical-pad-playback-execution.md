# Playback for arbitrary physical controller ports

`DemoPhysicalPadPlaybackExecution.v` constructs complete actual US/JP `run_demo_inputs` calls for any bounded first pad base, with either a disconnected second controller or a connected second pad at a later disjoint base in the same pad array. The aggregate is `generated_physical_playback_us_jp`, combining `generated_physical_connected_playback_us_jp` and `generated_physical_single_playback_us_jp`. Every record timer is covered, including EOF, record expiry and ordinary countdown; physical buttons and recorded inputs are arbitrary.

The first pad's base is any Z value between 0 and 18. For the connected case the second base has the same bounds, and `first + 4 <= second` separates the fields touched by playback. The actual controller-data pointers are `Vptr pads (Ptrofs.repr base)`. A standalone no-wrap lemma proves that actual field-pointer arithmetic for offsets 0 through 3 has the expected unsigned address `base + field`. The proof then executes the unmodified generated button normalization, P2 pointer test/clearing and demo record tail using those addresses. It does not enumerate or substitute artificial source programs for physical ports.

The source record formulas are unchanged: timer zero emits neutral first-player sticks and END buttons without pointer advance; timer one emits the recorded inputs and advances by four bytes; other nonzero timers emit the recorded inputs and decrement the timer. A connected second pad receives exact zeros at its X/Y/button fields, and those values survive the rest of the call. The final current pointer/timer and first pad fields are explicit conclusions. The byte frame excludes only the actual output pad field ranges, active record timer byte and current-pointer cell. The original four-byte header load is unchanged for records starting at offset at least four.

The two small port receipts establish that bases `6 * port` satisfy the numeric bounds for ports 0 through 3, and that `firstPort < secondPort` separates their pad fields. These algebraic receipts do not prove controller initialization. The theorem still requires the actual controller-data pointers, layout/symbol resolutions, a valid active record pointer, the actual record/input loads and writable destinations. The separate initialization proof must connect those premises to the first plugged physical ports and the generated six-byte pad layout. The local consumer itself performs no external SDK or math call.

This removes the previous consumer's fixed 0/6 pad configuration restriction. The complete post-polling caller and analog/copy boundaries must still be generalized and connected to initialization; the existing complete caller remains scoped to its stated configurations. Hardware polling contracts, buffer/record-bound induction, subsequent complete normal frames and whole-game exclusion of mismatched level transitions remain separate. Gameplay verdict: open.
