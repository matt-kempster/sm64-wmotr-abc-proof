# Complete post-polling controller execution for arbitrary physical ports

`DemoPhysicalControllerReadExecution.v` constructs the original generated US/JP `read_controller_inputs` continuation from immediately after hardware polling through its final player-three copy. The combined theorem is `generated_physical_controller_post_polling_us_jp`. It includes a single-controller theorem and a connected-second-controller theorem. The first pad base can be any value from 0 through 18. In the connected case the second base has the same bounds and `first + 4 <= second`; the actual initialized port bases are `6 * port`, with the first two plugged ports in scan order. The separate controller initialization proof is responsible for establishing those pointers. This module does not assume a whole controller-execution oracle.

Every demo timer branch is covered: ordinary countdown, four-byte record advance and zero-timer EOF. Physical buttons and prior button history are arbitrary. The actual generated consumer, first loop setup and nonnull test, first-controller record copy, arbitrary signed-stick analog call, increment and second-iteration setup, actual second-controller decision, second increment and loop exit, and final player-three copy are all composed using the original caller's `step2` semantics. The first controller's exact raw axes, transformed analog values, button-down and button-pressed formulas are conclusions. Player three receives the exact first-controller button fields. The connected second controller's seven fields are explicitly neutral with its supplied square-root result; when the second controller is absent, the original disconnected decision executes.

The theorem also preserves the exact controller-data pointers at bytes 24 and 52, the original demo header, and every entry valid access. The current-record pointer and timer have the same explicit formulas as the complete playback consumer. Those pointer formulas alone do not establish a valid next-record region. Other loaded cells retain their value when their byte ranges avoid the first pad's output fields, the connected second pad's output fields when present, the active timer byte, the current-pointer cell, and controller bytes 0 through 75. The finer component frames establish preservation of the data pointers inside that coarse controller range.

The nonnull test and shifted pad field addresses use the generated pointer arithmetic with a proved no-wrap bound. Controller structure offsets and the original analog function remain unchanged. The two-controller theorem has two precise named external `sqrtf` contracts: one at the exact emitted first-stick square sum, one at the neutral second-stick square sum. Each supplied call is trace-free and preserves its input memory. The neutral result additionally satisfies the generated magnitude-cap test. The single-controller theorem has only the first square-root contract. There is no supplied controller-copy or whole-loop execution premise.

This replaces the prior full continuation's fixed pad-0/6 restriction, subject to the stated initialization and memory premises. Actual hardware polling, successful allocation/DMA and authentic record provenance, record bounds across repeated calls, preservation by other gameplay work, retail-binary/hardware refinement and the full no-desync gameplay invariant remain open. The result begins at the post-polling continuation; it is not a normal-boot reachability theorem. Gameplay verdict: open.
