# Playback with the second controller connected

`DemoPlaybackSecondControllerExecution.v` constructs the complete actual US/JP `run_demo_inputs` call for every timer branch when logical controller one points to pads+0 and logical controller two points to pads+6 in the same memory block. Its aggregate is `generated_connected_second_playback_us_jp`.

The function first masks the first pad's physical buttons, then executes the real second-controller data-pointer test and three clearing stores: signed-byte X at pads+8 becomes zero, signed-byte Y at pads+9 becomes zero, and unsigned-16 buttons at pads+6 become zero. It then executes the original demo record tail. Timer zero emits neutral first-player sticks and END buttons; timer one emits the recorded sticks/buttons and advances the record pointer; other nonzero timers emit the recorded sticks/buttons and decrement the timer. Physical Start handling follows the same exact playback formula as the one-controller consumer.

The final result proves the second pad remains neutral after the entire call, gives the exact first-pad values and current pointer/timer, and preserves the original demo header word when the record starts at offset at least four. The byte frame excludes only the current-pointer cell [0,4), first pad bytes [0,4), second pad bytes [6,10), and the active record timer byte. This handles the first and second pads sharing one allocation. The proof supplies every actual source execution and introduces no SDK or analog external-call contract; `run_demo_inputs` itself has no such call.

The premises remain concrete local execution conditions: actual generated layout and symbols, the two controller-data pointers, readable record/input cells, a valid active record pointer and writable destinations. The 0/6 pad configuration corresponds to the first two physical pad slots. `init_controllers` actually scans all four physical ports and selects up to two plugged controllers, so this does not cover every hardware configuration. The [complete connected caller](connected-second-controller-read.md) now consumes this actual playback proof through both loop iterations and player-three copies. Other pad bases, boot initialization, record-region induction and the full gameplay no-desync invariant remain separate work. The gameplay verdict is open.
