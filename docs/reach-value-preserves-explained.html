reach_value_preserves the crux · false as written

A line-by-line reading of the one assumption that holds the actual A-Button-Challenge argument — why, taken literally, it is false for the real game, and what it has to become to be true. Companion to no-a-no-fly-explained.html.

The one-sentence version. The capstone reduces "no-A run never flies" to three assumptions; this is the load-bearing one. As stated it quantifies over every function in the game and claims none of them can turn the action flying — but set_mario_action(m, ACT_FLYING, 2) is a real function call that does exactly that. So the assumption is simply false, and the theorem currently rests on a false premise. The fix is not to delete it — it's to make it consume the no-A hypothesis it currently ignores. That fix is the unsolved core of the proof.
UPDATE — landed (2026-06-02). The false residual has been removed from the capstone. The single reach_value_preserves was decomposed (proved gluing lemma reach_value_preserves_noA_split) into: (W) reach_nonwriter_unchanged — every reached funcall that is not set_mario_action leaves the action cell untouched (TRUE, dischargeable); (writer) reach_writer_preserves_noA … NoA — the set_mario_action case, conditioned on a no-A memory predicate NoA (TRUE at the real NoA — the isolated crux); plus an input-grounding residual tying a_pressed = false to NoA, and the abstract NoA itself (the next thing to ground, in the controller bytes). The capstone is axiom-clean and no longer rests on a false premise. The walk-through below is why the original bare form was false — i.e. why this decomposition was needed.

1. The definition, line by line

From proofs/MarioModel/ActionValueFrame.v:362–367, verbatim, with a gloss beside each line. The capstone uses it at Q := nonflying, ge := mario_ge.

Definition reach_value_preserves (Q : int->Prop) (bm : block) (ge : genv) : Prop := A claim parameterized by a value-property Q (here nonflying = "not a flying constant"), Mario's struct block bm, and the global environment ge (here the real mario_ge).
forall m fd vargs t m' vres, The fatal quantifier. "For every memory m, every function definition fd, every argument list vargs, trace t, result memory m', result value vres." fd ranges over all functions — including the ones whose whole job is to change the action.
eval_funcall function_entry2 ge m fd vargs t m' vres -> IF one CompCert big-step call of fd with vargs, starting in memory m, produces memory m'…
Mem.valid_block m bm -> …and Mario's block is allocated in m…
action_sat Q m bm -> …and before the call the action cell holds only Q-values (non-flying)…
Mem.valid_block m' bm /\ action_sat Q m' bm. …THEN after the call Mario's block is still allocated and the action cell still holds only non-flying values. This is the part set_mario_action violates.

Unfolding the two helper names it leans on:

Definition action_sat (Q:int->Prop) m bm := forall v, Mem.load Mint32 m bm 12 = Some (Vint v) -> Q v. "Whatever 32-bit value the action cell (offset 12 of Mario's block) loads, it satisfies Q."
eval_funcall function_entry2 ge m fd vargs t m' vres CompCert's big-step judgement: calling fd (entered with the function_entry2 convention — params bound to temporaries, the clightgen calling style) runs the whole function body to completion, transforming memory m into m'. A whole call, callees and loops included.

2. Why it is false — the one-line counterexample

Pick fd := f_set_mario_action and vargs := [ &MarioState ; ACT_FLYING ; 2 ]. This is a genuine, reachable function in mario_ge. Run it from a perfectly good non-flying state:

m (before)
action cell @ (bm,12) = ACT_IDLE.
action_sat nonflying m bm ✓
valid_block m bm ✓
→
eval_funcall
f_set_mario_action
(m, ACT_FLYING, 2)
m' (after)
action cell @ (bm,12) = ACT_FLYING.
action_sat nonflying m' bm ✗
(ACT_FLYING is flying)

All three hypotheses held; the conclusion action_sat nonflying m' bm fails. So the forall fd statement is false at fd = set_mario_action.

This isn't a corner case or a modelling artifact. set_mario_action writing the action field is the mechanism by which the action ever changes. The definition says "no reachable call ever makes the action flying"; the game obviously contains a call that makes the action flying. The statement is just too strong.

Consequence for the capstone. Because this is a Section Hypothesis, the theorem noA_no_spawn_never_flying is of the shape reach_value_ok → … → no-fly. With reach_value_ok unsatisfiable for the real mario_ge, the theorem is currently (false) → no-fly — vacuously closed, saying nothing yet about real runs. This is the single biggest reason the proof "isn't done."

3. Why it's still the right residual (decompose, don't collapse)

The statement is false only because it ignores the no-A hypothesis. The honest theorem is conditioned: the run presses no A. The whole point of the A-Button-Challenge is that under no A, the flying writes are unreachable. So the residual is correctly located — it's the exact spot where the no-A argument has to be spent — it's just currently stated without the condition that makes it true.

Searching the real source, every site that puts Mario into a flying action is one of these five:

level_update.c:339 set_mario_action(m, ACT_FLYING, 2) Spawn hatch. Outside execute_mario_action; reached on a MARIO_SPAWN_FLYING warp. Excluded by the capstone's no_spawn_flying_run precondition.
mario.c:1050 set_mario_action(m, ACT_FLYING_TRIPLE_JUMP, 0) case ACT_DOUBLE_JUMP_LAND + wing cap. You only reach DOUBLE_JUMP_LAND by jumping (twice) and then jumping again — each jump is an A press.
mario_actions_moving.c:149 return set_mario_action(m, ACT_FLYING_TRIPLE_JUMP, 0) set_triple_jump_action + wing cap. The triple-jump dispatch — entered only when jumping out of a running landing. A press.
mario_actions_airborne.c:1710 set_mario_action(m, ACT_FLYING, 0) Inside act_shot_from_cannon — a SECOND entry into the flying set. ACT_SHOT_FROM_CANNON is not itself flying, yet it transitions to ACT_FLYING on a later, A-free frame (wing cap + falling). Entering the cannon (automatic.c:743) is A-gated, but the flying transition is multi-frame — see the taint-closure note below.
mario_actions_airborne.c:1934 set_mario_action(m, ACT_FLYING, 1) Inside act_flying_triple_jump — flying-set-INTERNAL. Fires from ACT_FLYING_TRIPLE_JUMP (already flying), so it never enters the set from outside; irrelevant to preserving "stay out of the set."
The shape of the truth — an inductive taint-closure, not a per-frame two-site check. The naive "non-flying → flying needs A this frame" is false: the cannon (ACT_SHOT_FROM_CANNON) is a non-flying state that goes ACT_FLYING on a later A-free frame. The honest invariant is stronger — carry action ∉ T, where T is the no-A reachability closure of the flying set (at least {ACT_FLYING, ACT_FLYING_TRIPLE_JUMP, ACT_SHOT_FROM_CANNON, …}). The ReachableRun induction then carries the multi-frame part for free, and the only per-frame obligation is: every entry into T from outside T is A-gated. Verified for all three in-gameplay entries — → FLYING_TRIPLE_JUMP (mario.c:1050, moving.c:149) and → SHOT_FROM_CANNON (automatic.c:743) are each under if (m->input & INPUT_A_PRESSED); → FLYING from spawn (level_update.c:339) is the excluded hatch. INPUT_A_PRESSED is set in exactly one place (update_mario_button_inputs), gated on the controller's A bit. Characterizing T (just those three, or more?) and proving its boundary is A-gated is the actual A-Button-Challenge.

4. What it has to become

The in-repo comment (ActionValueFrame.v:354–361) already names the discharge plan: a case split over the reached function.

(* case fd = set_mario_action *) It does write the action cell — but it writes the value of its second argument. Preservation needs: that argument is non-flying. Under the no-A taint invariant (action ∉ T) it always is, because every entry into T is A-gated. This is "brick 3" + the no-A taint-closure — the hard, open core
(* case fd = anything else *) It never writes the action cell at all, so action_sat survives by an unchanged-on argument ("brick 1"). This case is mechanical and within reach.

Concretely, the residual should be restated so it can consume the run's no-A condition — e.g. quantify only over funcalls reachable in a no-A frame (enumerate the finite call graph via CallgraphReach), rather than the bare forall fd over every function in the program. That restatement turns an unprovable assumption into a merely unproved one — which is the whole game (see the proof-discipline rule: "SM64 is one codebase, don't prove forall fd").

Bottom line. reach_value_preserves nonflying bm mario_ge is the crux, and right now it's false — not subtly, but at the most obvious function in the game. Everything the capstone "proves" sits on top of it, so until it's restated to use the no-A hypothesis and then discharged, the no-A ⇒ no-fly result is a scaffold around an empty center.
But it's the right empty center. The residual is correctly placed: it isolates the exact claim the A-Button-Challenge is about — "with no A, you can't reach a flying action" — and the source evidence (five flying sites, all jump- or spawn-gated) shows that claim is true and has a concrete discharge path (case-split: set_mario_action by non-flying argument, everything else by unchanged-on). Pouring this beam is the next real work, not more scaffolding.
