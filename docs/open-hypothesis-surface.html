1 · The theorem and its dependency tree

The live capstone (proofs/NoAImpliesNoFly/NoAImpliesNoFlyLinked.v, Section NoARealInput), verbatim:

Theorem noA_no_spawn_never_flying_real :
  forall (init : mem) (is : list mem) (m : mem),
    mem_ok_lp lp bm MWF init ->                          (* P1: well-formed start, action ∉ T *)
    Forall (fun i => a_pressed_real bm i = false) is ->  (* P2: the A_BUTTON bit is never set *)
    Forall (fun i => spawn_flying i = false) is ->       (* P3: no flying spawn-warp *)
    reachable mem mem step_real init is m ->             (* P4: m reached by real frames *)
    ~ mem_flying_lp bm m.                                (* Mario's action is never flying *)

where step_real i m m' := i = m ∧ execute_mario_action_step_lp lp m m' — one big-step eval_funcall of the real, clightgen'd f_execute_mario_action over the linked genv — and a_pressed_real literally chases gMarioState->controller->buttonPressed (offsets 156, 18) and tests bit 0x8000. There is no abstract input model left: an input is the pre-frame memory, and the input→invariant bridge (input_grounds_noA_real) is a proved lemma, not an assumption.

  • The first five are classical logic / extensionality / proof irrelevance — Coq-stdlib and CompCert-library standards (the Dedekind pair enters through CompCert's use of R; proof_irr through composite-env/linkorder metatheory).

3 · Layer 1 — abstract objects awaiting concrete witnesses

lp : Clight.program  +  LO_mario : linkorder mario.prog lp  witness not exhibited
the linked program — the single biggest structural assumption

Every theorem on this page is of the form “for any program lp that mario.prog link-embeds into, …”. No concrete witness link mario.prog (mario_step, mario_actions_*, interaction, …) = Some lp has been exhibited yet. Until it is, the capstone constrains every possible linked SM64 — which is meaningful (the residuals range over lp's real genv) but not yet pinned to the game. Discharge path: the SymbolicLinking.v template (exhibit linkability TU-pair-wise via CompCert's link_prog conditions without normalizing the result — the vm_compute route OOMs). Note Phase B will additionally need linkorder tu.prog lp for the other 11 TUs — all corollaries of the same witness.

bm : block  no obligation
Mario's MarioState block — universally quantified, pinned per-run

Not an assumption to discharge: the theorem holds for every block bm satisfying the init precondition, and P1's gMarioState_wf_lp conjunct pins bm to whatever the in-memory gMarioState pointer designates. gMarioState is an uninitialized global (gvar_init = nil), so Mario's struct is a runtime block — bm abstract-but-pinned is the correct formulation, not a gap.

MWF : mem -> Prop  to instantiate
the auxiliary memory well-formedness invariant — a strong-enough one must be exhibited

A free parameter today. The theorem is only as strong as the MWF for which the §4 hypotheses can actually be proved — the trivial MWF := True satisfies its own preservation clauses but is too weak to discharge Hstore/Hreach_val's aliasing leaves. The intended witness is the MarioMemWF-style block-distinctness geometry (static globals ≠ bm, Object blocks ≠ bm), now necessarily extended with controller-block distinctness: NoA_real reads the controller block bc through (bm,156), so the stores the engine certifies must be known to avoid bc too — a new, MWF-shaped obligation discovered when the invariant was grounded.

reached_id : ident -> Prop  ·  reached_fd : Clight.fundef -> Prop  to instantiate
the concrete reached call-graph closure over lp — not yet computed

The capstone is parametric over which identifiers/fundefs count as “reached”; Hbcr and Hbodyrck (§4) constrain the choice. The concrete instantiation must be the finite call-graph closure of execute_mario_action over the linked program. What exists today: the mario.prog-internal slice — exactly 17 writer-free functions (docs/reachable-internal-graph.md, 0 indirect calls). What does not exist yet: the closure through the 7 dispatchers into the action TUs (the act_* handlers and their callees, including the one censused indirect call through common_landing_cancels's function-pointer parameter). Computing and certifying that list is Phase-B work.

spawn_flying : mem -> bool  permanent modeling variable
the spawn-warp exclusion bit — models code outside the frame

The sixth and last T-feeder, set_mario_initial_action (level_update.c — the spawn/warp path writing ACT_FLYING for the flying-spawn warps), is not inside execute_mario_action; it runs in the level script. The capstone excludes it by the P3 precondition through this abstract bit. It stays a modeling variable until the step relation models more of the game loop than the action frame (see §7, frame scope). It does not weaken the no-A claim — it is the formal rendering of “and you don't take a flying-spawn warp”, which the ABC route (WMotR) satisfies.

4 · Layer 2 — the seven engine hypotheses (verbatim, with discharge paths)

These are the Hypothesis declarations of Section NoARealInput — the complete list; the capstone proof consumes exactly these seven plus LO_mario. Throughout: NoA_real m := ctl_a_clear m bm (the controller A-bit is clear), not_tainted v := is_tainted v = false with T = {ACT_FLYING 0x10808899, ACT_FLYING_TRIPLE_JUMP 0x03000894, ACT_SHOT_FROM_CANNON 0x00880898}, and lp_ge lp := globalenv lp.

H1 · Hreach_val  THE CRUX — Phase B
the value engine's per-funcall contract at the concrete invariant
reach_value_preserves_reached not_tainted bm (lp_ge lp) NoA_real MWF reached_fd
(* unfolds to: *)
forall m fd vargs t m' vres,
  reached_fd fd -> NoA_real m -> MWF m ->
  (marg_exempt fd = false -> marg_ok bm vargs) ->
  eval_funcall function_entry2 (lp_ge lp) m fd vargs t m' vres ->
  Mem.valid_block m bm -> action_sat not_tainted m bm ->
  Mem.valid_block m' bm /\ action_sat not_tainted m' bm /\ MWF m'.

Plain terms: every reached function of the linked program, called with Mario's pointer well-formed (marg_ok: arg0 into bm ⇒ offset 0), in a memory where the controller A-bit is clear and the action is outside T, returns with the action still outside T. This is where the actual SM64 content lives — that under no-A, no handler body ever writes a tainted action. It is satisfiable precisely because the invariant is T (the cannon edge is inside T) and the A-entries are gated (Taint.v/AGates.v). Discharge mechanism: the proved exec_funcall_reach_value_reached at ge := lp_ge lp — which reduces this single hypothesis to the 20 leaves of §5.

H2 · Hrest  flagged: forall-fd phantom
the “rest” residual: NoA + the two pointer-chase invariants survive funcalls
reach_rest_marg_lp lp bm NoA_real
(* unfolds to: *)
forall m fd vargs t m' vres,
  NoA_real m -> marg_ok bm vargs ->
  eval_funcall function_entry2 (lp_ge lp) m fd vargs t m' vres ->
  marioObj_wf_lp lp m bm -> gMarioState_wf_lp lp m bm ->
  NoA_real m' /\ marioObj_wf_lp lp m' bm /\ gMarioState_wf_lp lp m' bm.

Plain terms: any function call (with marg-shaped args) preserves the clear A-bit, the gMarioState → bm pointer cell, and the bm->marioObj pointer cell. Honest flag: as stated this quantifies over every fd in the universe, not just reached ones — the proof-discipline “phantom forall” pattern (an adversarial fundef could write anything). Its discharge therefore goes through a restatement sharpened to reached_fd-gated form (exactly the surgery already performed on the retired reach_value phantom), followed by the same census walk as H1. This is a known, planned capstone edit, not a surprise — recorded here so the page stays honest about it.

H3 · Hext  not derivable from CompCert's axioms
genuine externals preserve everything
forall ef vargs mm tt vres mm',
  NoA_real mm -> meminv_lp lp not_tainted bm mm -> MWF mm ->
  external_call ef (lp_ge lp) vargs mm tt vres mm' ->
  NoA_real mm' /\ meminv_lp lp not_tainted bm mm' /\ MWF mm'.
(* meminv_lp = valid_block bm /\ action_sat not_tainted /\ marioObj_wf /\ gMarioState_wf *)

Plain terms: the genuinely external functions the linked frame can reach (math/runtime: trig-table lookups, sqrtf, …) do not write Mario's action, his pointer cells, or the controller A-bit. Over lp this ranges over real externals only — the action dispatchers are Internal — so it is true of the game. But it is not provable from CompCert's axioms: external_functions_sem is an abstract parameter whose properties (ec_readonly etc.) do not bound writes to writable memory. So H3 either (a) remains a quarantined modeling assumption — “the math externals are pure”, stated per-named-external, or (b) is eliminated by linking those bodies too (the trig tables are data + lookup code). Until then it sits on the blue (trust) side of the ledger, not the amber one.

H4 · Hstore  needs controller-block geometry
the root body's two censused stores preserve the clear A-bit
forall e le mm a1 a2 tt le' mm' out,
  NoA_real mm -> RealFrameValue.prov_ok (Sassign a1 a2) ->
  exec_stmt function_entry2 (lp_ge lp) e le mm (Sassign a1 a2) tt le' mm' out ->
  NoA_real mm'.

Plain terms: prov_ok pins Sassign a1 a2 to one of the exactly two stores in f_execute_mario_action's own body (both through the marioObj Object pointer — vm_compute'd census). The claim: those two stores never touch the controller's buttonPressed halfword. True by block distinctness (the Object block ≠ the controller block), but proving it needs the bc-distinctness geometry that the chosen MWF (§3) must carry — the concrete new obligation that grounding NoA surfaced.

H5 · Hstoremwf  depends on the MWF witness
the same two stores preserve MWF
forall e le mm a1 a2 tt le' mm' out,
  NoA_real mm -> RealFrameValue.prov_ok (Sassign a1 a2) -> MWF mm ->
  exec_stmt function_entry2 (lp_ge lp) e le mm (Sassign a1 a2) tt le' mm' out ->
  MWF mm'.

Plain terms: the root body's two Object-pointer stores keep the memory well-formedness invariant intact. Cannot be attacked until MWF is instantiated (§3); for the intended block-distinctness MWF this is the standard store-off-the-watched-blocks argument already proved once at mario_ge (store_preserves_meminv family) — re-derivation over lp_ge, mechanical.

H6 · Hbcr  per-id resolution over lp
the syntactic→semantic call bridge: censused calls resolve to reached fundefs
forall oid a al e le mm vf fd,
  RealFrameValue.reach_chk reached_id (Scall oid a al) ->
  eval_expr (lp_ge lp) e le mm a vf ->
  Genv.find_funct (lp_ge lp) vf = Some fd -> reached_fd fd.

Plain terms: if the syntactic census approves a call site (a direct Evar id call with id ∈ reached_id; indirect calls are censused False), then whatever fundef the semantics actually resolves at that site is in reached_fd. Discharge: once reached_id/reached_fd are concrete finite sets (§3), this is per-identifier symbol resolution over the abstract lp — exactly what SymbolicLinking.v already provides (linkorder_resolves_funct, resolves_dispatch_{1..7}), iterated over the reached list.

H7 · Hbodyrck  decidable once reached_id is concrete
the root body passes the call census
RealFrameValue.reach_chk reached_id (fn_body mario.f_execute_mario_action)

Plain terms: every call in execute_mario_action's body is a direct call to a reached identifier. The body is concrete generated AST; with a concrete reached_id this is a vm_compute/reflexivity-class computation. (No instance has been proved yet at any scope — it awaits the §3 instantiation, but it is the cheapest row on this page.)
