Super Mario 64 · Wing Mario over the Rainbow · A-button challenge

Without A, Mario can’t get high enough.

This project is building a Coq proof, checked against the game’s own compiled C, that red coin #2 in WMotR is out of reach if you never press A. The picture on the right is the whole idea, drawn to scale.

  1. The highest floor you can stand on is 2424. It’s the top of the wing-cap box at y = 2320 (the box is scaled ×2, so its top sits 104 up).
  2. No move without A gains more than 372. We know because we found every line of code that writes Mario’s y (the crawl, below). The biggest gain is the slide-kick bounce: 370.6, plus float rounding.
  3. So Mario never gets above 2796, and there is no floor between 2424 and 3046 to climb onto next.
  4. Coin #2 needs 2980. It floats at 3140, and Mario’s body is 160 tall. That leaves 184 units to spare.

How we can bound the height at all

Mario’s y only changes where the code writes it. So we found every write.

Mario’s height is one float in memory, MarioState.pos[1] at byte offset 64. Nothing moves him up or down unless some line of C stores a new value there. So instead of reasoning about gameplay, we crawled the generated code for every store that can reach that float, either as a direct field store or through a whole-vector copy like vec3f_copy(m->pos, …). Coq does the crawl itself (YWriterCensus.v): it scans every function of the twelve Mario files and proves there are exactly 52 such sites, and that the address of pos never hides in a variable or in memory where a later write could use it. Each site is sorted into a bin. Tap one to see it.

Tap a numbered site to see where it is and what it writes.

Climbing is bookkept, not guessed

Only the climb bin raises y freely, and it is really one operation: y += vel / 4, four times a frame, while gravity pulls vel down. So the budget counts height plus the rise the current speed can still buy. A step spends that credit to gain height and never creates any. The same crawl over vel[1] shows that without A, no launch sets more than 52 upward speed (a slide kick at most 30), so the credit starts small.

Snaps land on real floors

Every snap writes a floor, ledge or pole height taken from the level. The level data proves no floor exists between 2424 and 3046, and a snap only reaches a floor within 241 of where Mario already is. So no snap carries him across the gap.

What each site does is now proved too

The list of sites is machine-checked, and so is what the sites in reach do: all 11 no-A airborne actions (freefall, dive, knockbacks, ground pound, slide kick …) are walked through their real handlers, and the pole, ledge and cannon rows likewise. What is left in Mario’s own update is 7 named per-call rows (below). The machine-checked census found 12 sites that the hand-written census had merged together.

How the proof works

One frame goes in. The machine stamps it “still below 2796”.

The theorem runs a frame through the same phases, in the same order, as the real game loop. If Mario’s height budget holds going in, it holds coming out, and the loop repeats every frame. Paused, transition and time-stop frames take a shorter path through the same phases. Tap a part to see what it says and what holds it up.

Things that were wrong, and got found

A proof that only ever confirms is suspicious. These are claims that looked right until the proof, or tethering it to the real game, said otherwise.

2026-10-25

Objects write Mario’s state. The plan assumed each object only touches itself. A census of the real code found pushes moving Mario’s x and z, 1-ups changing his lives, NPC dialog setting his action, and the cannon flagging him. Each now has its own contract proved from the real code.

2026-10-25

Several world facts were false or quantified over impossible states. Mario’s area pointer is &gAreaData[i], not a fresh block; a collided object was allowed to be Mario himself; throwMatrix, sWarpDest and the credits pointer were never pinned. All fixed and re-proved from the real boot state.

2026-10-25

“The run gets stuck there” is not a proof. An unchecked action-table index makes Clight stop, which silently drops those runs instead of covering them. The rule is now: carry the in-range fact as an invariant, and log the site as an undefined-behaviour coverage point.

2026-10-24

Rotating platforms move Mario’s height, and cannon bases rise. Two specs said otherwise. Both were restated from the real code (140 cannon seats walked one by one), and “nothing Mario rides in WMotR rotates” was proved from a census of every rotation-speed store.

2026-10-23

An unplugged controller reads as “A pressed”. A no-A premise over every port would have been false with fewer than four controllers, making the theorem vacuous. The premise now ignores error-flagged ports, as the game does.

2026-10-18

Both capstones were vacuous for a day. The memory invariant only allowed one global to hold Mario’s pointers, but the real init stores three more. No real memory satisfied it. Widened, and now proved true of the memory right after the real boot and init.

2026-09-27

The collision check has no return value when objects miss sideways. In the ROM, detect_object_hitbox_overlap falls off its end, so it returns whatever is in the register. Our C returns 0 there. The coin theorem was restated so the returned value doesn’t matter: it proves only that the check returns without touching memory.

2026-09-27

Exclamation boxes are twice as tall as we thought. The game scales object collision by the object’s size, and the box runs at scale 2. Its top is y + 104, so the highest floor moved from 2372 to 2424 and the margin to coin #2 dropped from 236 to 184. Found by decoding the real level data.

2026-09-27

The slide kick gains more than we thought. An earlier estimate of the biggest no-A gain (273) missed that slide-kick gravity is only −2 and that its timer survives the bounce. The real peak is 370.6, which is why the budget is 372.

2026-09-26

Grabbing a pole doesn’t need A. Only the handstand jump at the top does. So poles count as ladder rungs, and each pole’s grab window has to start above the ceiling.

2026-09

The proof was leaning on undefined behavior. VIRTUAL_TO_PHYSICAL ANDs a pointer, which CompCert treats as undefined. 33 of 300 real frames had no execution, and one step of the proof used that as a contradiction. The site was rewritten to the same bits in defined C (TRUST 2.2), and now all 300 frames replay byte-for-byte.

2026-07

Four assumptions that were false about the real game. Examples include bully aliasing and a sound-flag OR. They were green and axiom-clean but claimed things over states the game never produces. All four were restated.

Where the work goes from here

Discharge the object stages

The real object update is in the frame; now prove its stage rows: the list loops, the behaviour interpreter, collisions, the surface reset and unloading.

Restate GOAL 1 over the whole frame

Today GOAL 1 covers only Mario’s own update. Once objects land, state “no A ⇒ no flying” over the full real frame, so object-driven action changes (the cannon) are covered.

Cover undefined behaviour

Prove the frame never gets stuck from any invariant state, so runs that would hit UB are ruled out, not just skipped. Model any real UB site from the N64 memory layout.
