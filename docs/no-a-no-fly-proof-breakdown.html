no-A ⇒ no-fly: the proof from scratch

A ground-up tour of the GOAL-1 capstone noA_no_spawn_never_flying as it stands today — what it claims, how it is built out of a value-flow engine over the real game code, which pieces are genuinely proved, and the one honest phantom that remains. Nothing rounded up. Snapshot: commit 8ac2823 (2026-06-03).

The one-paragraph status. The theorem's endpoints are real: step is the mechanically-generated Clight of SM64's execute_mario_action, and "flying" is the real 32-bit action field loaded at the real offset of the real MarioState. The argument reduces "no reached function writes a flying action" to a finite, machine-checked set of 17 functions the frame actually reaches, proved closed under calls, whose bodies are certified by a decidable census. The aliasing reasoning that the census rests on was, until this week, propped up by a false invariant; that has been corrected to a true one. What is left is one named block-distinctness brick (store_root_offbm) plus the cross-translation-unit linking residuals — all explicit hypotheses, none hidden.

1. What is being claimed

The A Button Challenge asks whether Mario can ever fly without the A button. GOAL 1 proves the contrapositive half of one direction: a run in which A is never pressed (and no flying-spawn warp fires) never reaches a flying action. "Flying" is not a hand-written predicate — it is the actual integer in Mario's action cell:

mem_flying m :=
  ∃ v, Mem.load Mint32 m bm 12 = Some (Vint v)
    ∧ is_flying_int v = true		 Mario's struct lives in block bm; his action field is the 4 bytes at offset 12 (computed by vm_compute over the real composite environment, not asserted). is_flying_int tests the action against the real ACT_FLYING / ACT_FLYING_TRIPLE_JUMP / ACT_SHOT_FROM_CANNON constants. So "fly" means the real game would report a flying action.

The capstone (proofs/NoAImpliesNoFly/NoAImpliesNoFly.v) folds the real per-frame step over a list of inputs and concludes Mario is never flying:

Theorem noA_no_spawn_never_flying : The claim is its name.
 ∀ init is m,a start memory, a run (list of per-frame inputs), an end memory.
  mem_ok init →starts good: Mario allocated, non-flying, and memory well-formed (MWF).
  noA_run_real is →every frame has a_pressed = false.
  no_spawn_flying_run is →no frame fires a MARIO_SPAWN_FLYING warp (WMotR's level has none).
  reachable step init is m →m is reached by folding the real execute_mario_action step.
  ¬ mem_flying mconclusion: the end memory is not flying.

step is a real fragment of a frame (execute_mario_action, not the whole thread5_game_loop iteration); the frame→fragment reduction is an honest small assumption, justified because Mario's action is only written inside that subtree or level_update.c's spawn switch. See theorem-scope.

2. The shape of the argument

One frame either keeps Mario non-flying or it does not. The proof never reasons about "the run" directly; it shows each single frame preserves non-flying, then induct over the list. A frame is one big-step eval_funcall of execute_mario_action, which calls other functions, which call others. So the real content is: across that whole call tree, the only thing that can land a flying value in the action cell is the designated writer set_mario_action — and under no-A it is never asked to write a flying value.

3. The ~61 → 17 reduction (now sound)

mario.c has ~61 internal functions other than set_mario_action. The frame does not reach all of them. reached_funcs is the explicit list of the 17 that execute_mario_action can actually call (transitively, minus the writer). Two machine-checked facts make restricting attention to those 17 sound:

reached_fd_reach_chk : every reached body's
direct calls all target a reached_id
(no indirect/function-pointer calls)		 Static call-graph closure. vm_compute over the 17 real bodies: the reached set is closed under direct calls. This is what lets the engine's "the callee is reached" leaf (reach_call_reached) fire only for reached targets instead of asserting the false "every call resolves to a reached function".
reached_funcs_no_action_store
reached_funcs_marg_arg_chk
reached_funcs_sset_chk		 Body census (= true on all 17, by computation): no body names Mario's action field as a store target; every call's Mario argument is a temp; no Sset can install a misaligned Mario pointer. These are the conjuncts of C (below).

The exempt 17th (vec3f_find_ceil, whose first parameter is a float* not a MarioState*) writes no memory directly; its only effect is the external find_ceil call, and its whole-funcall preservation is proved separately (reach_vec3f_preserves).

4. The body census C and the temp invariant TI′

The engine carries two facts that the body leaf must re-establish. C is a decidable, four-conjunct census of a statement; TI′ is a provenance invariant on the temporaries.

C s := no_action_store s = true
 ∧ reach_chk reached_id s
 ∧ marg_arg_chk s = true
 ∧ sset_chk s = true		 (1) no Sassign targets Mario's action field (store-shape census); (2) every direct call targets a reached id, no indirect calls (closure); (3) every non-exempt call's argument 0 is an Etempvar (makes the marg-arg bridge sound); (4) every Sset source is a shape that can never produce a misaligned Mario pointer (rejects &m->field and pointer arithmetic; accepts loads/temps/scalars/casts). All four = true on the 17.
TI′ le := ∀ t b o,
 le!t = Some (Vptr b o) → b = bm →
 o = Ptrofs.zero		 Every temporary that holds a pointer into Mario's block holds it at offset 0 — no temp ever holds a misaligned Mario pointer. Established at function entry (only the parameter _m is a pointer, and it is (bm,0)); preserved across Sset by the census (4).
This week's correction. TI′ replaced a false predecessor. The old invariant was "only _m may hold a Mario pointer." That is simply untrue of the real code: mario_update_hitbox_and_cap_model reloads the global gMarioState (= Vptr bm 0) into ordinary temporaries. So non-_m temps do hold Mario pointers — but always aligned (offset 0). TI′ ("aligned, if Mario") is the true invariant, and it is exactly what the direct-store argument needs. With it, the once-false reach_TI_set (TI is preserved by a censused Sset) became true as written.

5. The store-aliasing core

The body leaf's hardest job: show that a censused body's stores cannot hit Mario's action cell (bm, [12,16)). Every store falls into one of three shapes, and assign_avoids_action_cell dispatches on them:

Evar g — a global/local
Store block ≠ bm because bm is a runtime block distinct from every program variable (bm_not_var). proved (modulo that runtime fact).
m->f — a direct field of Mario
Block bm, offset = field_offset f; by TI′ the base is (bm,0) and the census certifies the offset range misses [12,16). proved (m_direct_avoids, pure layout arithmetic).
chase stores — p->...[i]
Through a chased pointer (marioObj, marioBodyState, a matrix). Safe because that pointer points off Mario's block. store_root_offbm

The third shape is the one honest gap on this path. The off-_m store roots in the 17 bodies are chase pointers — m->marioObj (an Object*), m->marioBodyState, a 4×4 matrix — and a store like marioObj->header.gfx.scale[i] uses a dynamic index, so no static offset bounds it. It is safe only because the chased pointer lands off bm, which is a heap fact (block-distinctness) the abstract MWF is meant to supply:

Hypothesis store_root_offbm :
 ∀ e le m a1 loc ofs bf t,
  eval_lvalue … a1 loc ofs bf → MWF m → TI′ le →
  store_root a1 = Some t → t ≠ _m →
  rooted_lv t a1 = true → loc ≠ bm		 The MarioMemWF block-distinctness brick. True for the real program (verified: no reached body roots a store at a gMarioState-reloaded (bm,0) temp). But, as a standalone ∀ le statement, it is refutable by an adversarial le that puts (bm,0) in a store-root temp — a state the real run never produces, but this form does not forbid. Its full discharge needs execution-relative provenance: a correlated temp_env → mem invariant proving the chase temps are off-bm from MWF. That is the documented next step.
Why it was not simply eliminated. Two routes were explored. (a) A static cumulative-offset census discharges the direct field stores with no provenance at all (the MarioBodyState fields sit at offsets 4–8, Object hitboxHeight at 508 — all clear of [12,16)) — but it cannot touch the dynamically-indexed array stores, and generalizing the census to look up arbitrary large composites (Object) inside a vm_compute blows the build past its time limit. (b) The principled fix is to thread a correlated invariant through the engine so the store leaf knows the chase temps are off-bm; the engine currently threads TI′ : temp_env → Prop and MWF : mem → Prop separately, so the needed correlation is not yet expressible. Both are real work, deferred honestly rather than papered over.

What is genuinely proved (Lemmas, on the spine)

  • The 17-function reduction is sound — static call-graph closure (reached_fd_reach_chk) + the four census facts, all by vm_compute over the real clightgen'd bodies.
  • The body leaf (reach_value_body_marg): every reached internal's entry establishes TI′ and its body satisfies C.
  • The value engine (exec_funcall_reach_value_reached): the mutual induction threading NoA/MWF/TI′/C and isolating the single writer.
  • The direct-store aliasing (assign_avoids_action_cell for Evar + m_direct_avoids): global stores miss bm; Mario-field stores miss the action offset by layout.
  • TI′ preservation lemmas (entry_TI_singleparam, reach_TI_optc/optb, reach_C_*) and the exempt-callee leaf (reach_vec3f_preserves).

7. Verdict

Have we made real progress, and where exactly is the frontier? Yes. The endpoints are the real game; the ~61→17 reduction is sound and its decidable core is proved; the body census is machine-checked; and the provenance invariant that the whole store argument rests on has gone from false to true. The frontier is now a single, named, well-understood residual on the store path — store_root_offbm, the block-distinctness fact that the array/nested chase stores point off Mario's block — plus the standing cross-translation-unit linking and NoA-grounding residuals. The capstone reads IF (a precise, true-for-the-real-program, not-yet-discharged set of bricks) THEN no-fly, no longer IF (something false) THEN …. The next concrete step is to thread a correlated temp/memory invariant through the value engine so store_root_offbm can be proved from MWF rather than assumed.
