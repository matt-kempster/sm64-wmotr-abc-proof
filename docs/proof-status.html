Super Mario 64 · A-Button-Challenge impossibility · Rocq + CompCert

Can “Wing Mario over the Rainbow” be beaten without pressing A?

The project aims at a machine-checked no: a Coq theorem, grounded in the mechanically-translated (clightgen) C of the actual game, that WMotR’s star is unreachable under never-press-A inputs. It splits into two goals.

GOAL 1 · COMPLETE no-A ⇒ Mario never enters a flying action GOAL 2 · ON THE SPINE without flying, Mario’s height stays below the star Last updated 2026-09-26

GOAL 1 — no-A ⇒ no-fly proved

Seven audited theorems, all passing the discipline audit (build · no admits · standard CompCert axioms only · firewall clean). The sharpest form:

noA_no_spawn_never_flying_linked12

For any CompCert link of the twelve clightgen’d action TUs: starting from a well-formed memory, repeatedly running one real execute_mario_action with the A bit clear never produces a flying action. Scope: the step is Mario’s action update only; objects, level scripts and warps (which also write Mario’s state in the real game) are outside it. Companion theorems: linked12_inhabited (the twelve TUs provably link) and A_pressed_frame_reaches_flying — the positive control: with A pressed, one real frame goes from the double-jump landing (with the wing cap) to ACT_FLYING_TRIPLE_JUMP. It is proved by running the generated code in Coq with a sound interpreter, so the no-A premise is what does the work. Still open: a start memory that meets all the rows below.

The antecedent is not a hypothesis row

mem_ok_lp init — “the run starts in a well-formed WMotR spawn state” — is the theorem’s conditional. Discharging it would mean modeling boot + level-load outside the twelve TUs (inventing the initial state). The honest form is the conditional we have.

Tethered to the real game — differential testing

The model is now checked against the real ROM (sha1 matches the US baserom), running headless in an emulator. The recorder captures real WMotR frames of execute_mario_action. Each one is replayed through the proved-sound interpreter on a CompCert memory built from the real RAM, with the calls outside the link replayed from the game (callee and arguments must match). The final memory is then compared byte for byte (experiments/oracle/, ledger 5.1).

Found and fixed: the proof was using undefined behavior

All 33 STUCK frames had one cause. After a fresh animation DMA, set_mario_animation runs VIRTUAL_TO_PHYSICAL(ptr) = ptr & 0x1FFFFFFF. Bitwise AND on a pointer is undefined in CompCert C, so 11% of real frames had no execution, and a “for all executions” theorem said nothing about them. Worse, the spine's walker had discharged those stores by contradiction: it used the UB as a proof step. Fix: the policy is that the N64 is a real machine, so UB is really defined behavior. Each site is rewritten to CompCert-defined C with the same bits, and gets a ledger row (2.2 register, inventory in docs/ub-sites.txt). VIRTUAL_TO_PHYSICAL became ptr - 0x80000000, which is equal on every KSEG0 address. The dead-code proof arm is gone. A real one proves the stores safe, and the capstones stay clean. STUCK = 0 is now the regression gate.

History worth remembering: four hypothesis rows that looked fine were found false of the real game (vacuous capstone, bully aliasing, sound-flag OR, dead return-plumbing) and repaired — green-and-axiom-clean never means non-vacuous. The store-scout audit (classify every store against the generated AST) is the only method that caught them.

GOAL 2 — WMotR requires A active

Remaining gap: even without flying, could no-A Mario climb to the star some other way? The playground’s y-row was false too: y ≤ YMAX alone says nothing about upward velocity. It became the invariant row below.

Reading the colors

  • proved — a Qed’d theorem on the spine, standard axioms only.
  • assumed — dischargeable — a named hypothesis with a concrete discharge plan; the working scoreboard.
  • honest boundary — assumed by design: facts outside the verified TUs (object pool, run layout, CompCert’s external-call model). These are what the final theorem will ask a reader to accept.
  • active front — where current work is aimed.
