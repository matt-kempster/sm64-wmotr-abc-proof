De-vacuuming GOAL 1: the linking + A-gating roadmap

How noA_no_spawn_never_flying goes from vacuously true to a real theorem about the SM64 binary — the two phases, their costs, and what is already built.

The situation in one paragraph. The GOAL-1 capstone is currently vacuously true: it assumes reach_ext_action_cell, which says every external call leaves Mario's action field byte-unchanged — and at the single-TU scope (mario_ge = globalenv mario.prog) the per-action dispatchers mario_execute_*_action are underspecified Externals whose semantics admits writing a flying value. So the hypothesis is false, and a theorem resting on a false premise proves nothing. The fix is not to prove that hypothesis (it cannot be) but to replace it: link the action translation units so the handlers become real Internal bodies the value engine traverses, then prove — over real code — that under no-A no handler ever writes a flying action.

1 · Why the capstone is vacuous today

The value engine's external case routes every external call through the one hypothesis (ActionValueFrame.v:833):

(* eval_funcall_external — fires for any External callee *)
... eapply action_sat_unchanged_on; [ eapply Hext; exact Hec | ... ]
(* Hext := reach_ext_action_cell : reach_ext_preserves (action_cell bm) mario_ge *)
(* reach_ext_preserves P ge := forall ef .., external_call ef ge .. m .. m' -> unchanged_on P m m' *)

And mario.prog declares the dispatcher as an underspecified external:

(_mario_execute_airborne_action,
  Gfun(External (EF_external "mario_execute_airborne_action" ..) ..))

Instantiate ef at that dispatcher and pick the (allowed) behavior that writes ACT_FLYING to the cell: reach_ext_action_cell is refuted. The whole call graph where jumping, swimming and flying live sits behind this one false assumption. Print Assumptions stays clean because it detects Admitted/Axiom, not false Prop hypotheses.

2 · The fix: link the action TUs, re-root over lp

Linking moves the dispatchers out of the underspecified-external bucket. Over the linked program lp = link(mario, mario_step, mario_actions_*, interaction):

  • the dispatchers and act_* handlers are Internal — the engine's Scall→funcall path traverses their real bodies;
  • reach_ext_preserves (action_cell bm) (globalenv lp) now ranges only over genuine math/runtime externals (find_ceil, math builtins, memcpy) — where unchanged-on is true;
  • the action-writing logic is proven down to set_mario_action's no-A guard.

OOM discipline (non-negotiable). The first linking attempt vm_compute'd the merged program and OOM'd. The template (SymbolicLinking.v) keeps lp abstract — a link … = Some lp hypothesis, never normalized — and resolves every cross-TU symbol through CompCert linking metatheory (prog_defmap_linkorder + find_def_symbol). The only computations are per-TU defmap lookups. Never vm_compute lp's defmap or composite env.

4 · Phase A — re-root over lp ⇒ non-vacuity

This is the structurally mechanical (but large) half. The generic value engine exec_funcall_reach_value_marg is already parametric over ge. The work is that the frame wrapper execute_mario_action_preserves_real_reached (RealFrameValue.v:2439) is threaded through mario_ge everywhere:

(* every supporting lemma is mario_ge-specific *)
reach_meminv_reached_build  exec_body_prov_reached
execute_mario_action_body_prov_ok / _pgms_ok  funcall_from_body_preserves_entry

So Phase A = re-derive RealFrameValue's ~2400-line census / meminv / entry infrastructure over globalenv lp, and redefine step as the eval_funcall of f_execute_mario_action in lp. Substantial, but bounded and mostly mechanical: the censuses are decidable, the engine is generic.

The payoff is non-vacuity — even before any A-gating. Once re-rooted, every residual the capstone rests on is true: reach_ext over lp (genuine externals only), the decidable body censuses over lp's reached set, the link-existence fact, and the writer residual (now a true-but-hard A-gating, not a falsehood). The theorem flips from meaningless to conditionally true on real, satisfiable residuals. This is the single most valuable milestone.

5 · Phase B — the A-gated write-site closure (where flight lives)

The remaining content: prove the writer residual reach_writer_preserves_noA over lp — under no-A, set_mario_action is never called with a flying argument. ActionGraph.v already sizes this into two parts.

B1 · control-reachability
The 5 flying out-edges are literal constants (ACT_FLYING=277350553, ACT_FLYING_TRIPLE_JUMP=50333844) — pinned. Prove they are unreachable under no-A. This is the temporal, cross-frame taint closure: triple-jump flight needs consecutive A-jumps over prior frames, so a within-frame input check is provably insufficient (4/5 sites read no input in-frame). The WMotR argument proper.
B2 · dataflow
~46 setter calls pass a computed (variable) action argument (computed_count: moving 16, cutscene 8, airborne 6, object 5, stationary 3, mario 3, submerged 2, automatic 2, level_update 1). Rule out any carrying a flying value. The value engine tracks the real value semantically (action_sat), so re-rooting may subsume B2 — to be confirmed once the engine runs over lp.

7 · Recommended order

  1. Phase A first. It is the bounded milestone that earns non-vacuity and consumes the resolution layer already built. Until it lands, any A-gating proof stays Unwired.
  2. Then Phase B1 (the temporal taint closure) — promoting the ActionGraph/ActionWriters analyses into the inductive run invariant.
  3. B2 likely falls out of the re-rooted value engine; confirm rather than assume.
Honest status. reach_ext_action_cell still stands in the capstone — the theorem is not yet meaningful. What this roadmap buys is a checkable path: the linking foundation and the complete finite write-site set are built and verified; the remaining work is Phase A's re-rooting (large, mechanical) and Phase B's A-gating (the genuine WMotR research). Neither can be faked or one-shot; both are now decomposed into concrete, real-program steps.
