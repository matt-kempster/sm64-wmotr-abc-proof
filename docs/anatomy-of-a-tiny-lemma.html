Anatomy of a tiny lemma: proving return 0.0f; can't make Mario fly

A walkthrough of gayvfj_row — the preservation lemma for get_additive_y_vel_for_jumps, quite possibly the least important function in Super Mario 64 — and why the no-A-press impossibility proof was not allowed to skip it. (2026-06-05; artifacts in proofs/MarioModel/ActWriterSurface.v, the body in generated/mario_step.v:497.)

The one-sentence version. Somewhere inside the proof that Mario can never enter a flying action without an A-press, there is a five-artifact, ~25-line proof that a vestigial function whose entire body is return 0.0f; does not write to memory. Nothing about the theorem allowed us to assume that. This page uses it as a microscope slide: the same five-artifact pattern, at its absolute smallest, is the unit of work being repeated for every one of the ~234 functions still on the open surface.

1 · The function

In the SM64 decompilation (src/game/mario_step.c):

// The decomp notes this always returns zero; it is widely read as a
// leftover hook for cut content (the beta trampoline is the usual
// suspect). It shipped in the final game anyway.
static f32 get_additive_y_vel_for_jumps(void) {
    return 0.0f;
}

Its one caller is real jump physics, though: set_mario_y_vel_based_on_fspeed computes Mario's initial jump velocity as

m->vel[1] = initialVelY + get_additive_y_vel_for_jumps() + m->forwardVel * multiplier;

so this ghost of a cut feature sits in the middle of the expression that launches every jump in the game. What the proof actually reasons about is not the C but the mechanically clightgen'd AST (generated/mario_step.v:497), verbatim:

Definition f_get_additive_y_vel_for_jumps := {|
  fn_return := tfloat;
  fn_callconv := cc_default;
  fn_params := nil;
  fn_vars := nil;
  fn_temps := nil;
  fn_body :=
    (Sreturn (Some (Econst_single (Float32.of_bits (Int.repr 0)) tfloat)))
|}.

One statement. No parameters, no locals, no temporaries. The float literal is even spelled the honest way — Float32.of_bits (Int.repr 0), the IEEE-754 bit pattern, because that is what clightgen emits.

2 · What we proved

The lemma (ActWriterSurface.v:4025):

Lemma gayvfj_row :
  call_pres lp bm NoA MWF mario._get_additive_y_vel_for_jumps.

where call_pres unfolds to a statement about every big-step execution of whatever fundef the linked program resolves that identifier to:

forall fd m0 vargs t m1 vres,
  eval_funcall function_entry2 (lp_ge lp) m0 fd vargs t m1 vres ->  (* a real call runs *)
  resolves_lp lp mario._get_additive_y_vel_for_jumps fd ->          (* of THIS symbol *)
  marg_ok bm vargs ->                                               (* Mario-arg shape (vacuous: nullary) *)
  NoA m0 -> MWF m0 -> Mem.valid_block m0 bm ->
  action_sat not_tainted m0 bm ->                                   (* action ∉ {flying…} before *)
  Mem.valid_block m1 bm /\ action_sat not_tainted m1 bm /\
  MWF m1 /\ NoA m1.                                                 (* …and after *)

In plain terms: if Mario's action is not in the tainted set (FLYING, FLYING_TRIPLE_JUMP, SHOT_FROM_CANNON), the controller's A-bit is clear, and memory is well-formed, then after any actual call to this function all of that is still true. For a function that provably never touches memory, this is the weakest interesting thing one could say — and it still has to be said, formally, because the theorem's induction demands it.

3 · Why we proved it

Proximally: it was demanded by the callee census one level up. The live capstone rests on per-dispatcher callee censuses; chasing one chain from the top:

noA_no_spawn_never_flying_real_mwf → (engine v2: every reached funcall must preserve the invariant) → the action-handler leaf censuses → set_mario_action (the writer keystone — every action change in the game funnels through here) → set_mario_action_airborne (its airborne sub-setter: jump setup) → set_mario_y_vel_based_on_fspeed (the jump-velocity formula) → get_additive_y_vel_for_jumps (…the ghost)

The walker lemma for set_mario_y_vel_based_on_fspeed certifies its body statement-by-statement, and when it reaches the call statement it needs a call_pres fact for the callee. Its callee census is smyv_ids = [_get_additive_y_vel_for_jumps]; gayvfj_row is the row that feeds it. No row, no smyv_row; no smyv_row, no airborne sub-setter; no sub-setter, no set_mario_action keystone; no keystone, no capstone.

Distally: the theorem quantifies over executions, not over our beliefs about functions. The conclusion has the shape “for every memory reachable by real frames, the action cell is not flying” — and the only way an induction over real executions goes through is if every function the execution can enter carries the invariant across itself. There is no rule of inference that says “this one is obviously harmless.” A human can see return 0.0f; and move on; the proof checker cannot, and should not — the whole value of the exercise is that “obviously” gets replaced by a checkable artifact. Put differently: the proof's trust base is the clightgen pipeline and CompCert's semantics, not anyone's ability to eyeball C code. The day someone asks “but how do you know no helper function sneaks a store into the action word?”, the answer is: because there is a lemma like this one for every helper on every reachable path, and the kernel checked all of them.

There is also a subtler distal reason this function could not be waved off: it is called during jump setup, i.e. exactly when the action word is being rewritten by the writer family. The invariant is at its most exposed right there — the walker is mid-way through certifying a body that does store to Mario's struct. An unaudited callee at that point could break the action-value tracking even without writing the action cell itself (e.g. by clobbering the controller's button halfword and un-grounding the A-gate argument). So the row really is load-bearing; it just happens to be trivially true for this body.

4 · How the proof works — the five artifacts

The pattern is two-layered: syntactic facts established by computation (vm_compute over the generated AST — fast, no human reasoning) and one semantic lemma that consumes them through a generic, proved-once walker theorem.

① gayvfj_pin — the defmap pin
“the identifier resolves to THE generated body” · proof: vm_compute. reflexivity.
(prog_defmap mario_step.prog) ! mario._get_additive_y_vel_for_jumps
  = Some (Gfun (Internal mario_step.f_get_additive_y_vel_for_jumps)).

This is the PIPELINE tether: every later step reasons about f_get_additive_y_vel_for_jumps the clightgen output, pinned by computing over the whole translation unit's definition map. Combined with the link-order hypothesis linkorder mario_step.prog lp, it also pins what the linked program resolves the symbol to — so the lemma is about the game, not about a copy we wrote down.

② gayvfj_vars + ③ gayvfj_params — the shape pins
“no stack locals, no parameters” · proofs: vm_compute. reflexivity.
fn_vars   f = nil      fn_params f = nil

fn_vars = nil means function entry allocates no stack blocks (so entry itself cannot disturb memory accounting), and fn_params = nil makes the Mario-argument precondition marg_ok vacuous — this is a nullary leaf, the simplest entry shape the framework supports (call_pres_of_wwalk0).

④ gayvfj_walk — the walk
“the body passes the store/call census with ZERO allowances” · proof: vm_compute. reflexivity.
wwalk_chk false nil nil nil nil nil nil
  (fn_body mario_step.f_get_additive_y_vel_for_jumps) = true.

wwalk_chk is a boolean function that recurses over a statement AST and approves only statements it has a semantic brick for: censused window stores, censused calls, harmless Ssets, returns. All seven censuses here are nil — the body must contain nothing that needs an allowance. It is one Sreturn (Some literal); the walker's return rule for a plain helper (rt = false) accepts any returned expression, because expression evaluation in Clight is pure with respect to memory and call_pres promises nothing about the returned value.

⑤ gayvfj_row — the semantic row
the only “real” proof, and it is 10 lines of plumbing
Lemma gayvfj_row : call_pres lp bm NoA MWF mario._get_additive_y_vel_for_jumps.
Proof.
  apply (call_pres_of_wwalk0 mario_step.prog
           mario._get_additive_y_vel_for_jumps
           mario_step.f_get_additive_y_vel_for_jumps nil nil nil nil
           LO_mario_step gayvfj_pin gayvfj_vars gayvfj_params).
  - intros fid' H. discriminate H.   (* no internal callees *)
  - intros fid' H. discriminate H.   (* no writer callees *)
  - intros fid' H. discriminate H.   (* no external callees *)
  - intros fid' H. discriminate H.   (* no act-writer callees *)
  - exact gayvfj_walk.
Qed.

All the actual semantic work lives in two generic, proved-once theorems this applies: call_pres_of_wwalk0, the funcall→body bridge (inverts the big-step eval_funcall for an Internal fundef: entry allocates the — empty — locals, binds the — empty — parameters, runs the body, frees the — empty — block list), and wwalk_pres, the walker soundness theorem: an induction over the exec_stmt derivation showing that every statement the boolean walk approved preserves valid_block bm ∧ action_sat ∧ MWF ∧ NoA. For this body the induction visits exactly one case — Sreturn — whose proof obligation is “evaluating the return expression doesn't change memory,” which holds by the shape of Clight's semantics. The four discriminate bullets dispatch the per-callee obligations for the four empty censuses: membership in nil is a contradiction.

Then the row gets consumed — smyv_ids_rows keys it into the callee table for set_mario_y_vel_based_on_fspeed, whose own row feeds the airborne action-setter. This step matters for hygiene: the repo's CI treats a proved but unconsumed lemma as staging (check_unwired), so “we proved a thing about the ghost function” only counts because something on the capstone's path uses it.

5 · Extra notes

  • Cost accounting. Five artifacts, ~25 lines, four of them one-liner vm_computes. That is the marginal cost of a trivial leaf in this framework — the design goal of the walker architecture. The expensive things were built once: the walker soundness induction (~1500 lines with its store bricks) and the entry bridges. The ~234 leaf bodies still open on the capstone surface each cost roughly this much plus whatever allowances their bodies actually need (a window store here, a chase-pointer store there) — this function is the pattern at allowance-zero.
  • Why a float function shows up in an integer-action proof at all: nothing about the action word involves vel[1] — but reachability, not relevance, is what obligates a row. The call cone of the action dispatch is the boundary of the proof, and jump physics is squarely inside it.
  • The N64 flavor. Even here the platform model matters a little: the return literal elaborates through CompCert's 32-bit big-endian PowerPC parameterization (the repo's N64 stand-in), and tfloat is IEEE-754 single — the proof's Float32.of_bits is the same bit pattern the console would load.
  • The game-history footnote. The decomp community reads this function as a leftover hook for cut content (the beta trampoline is the perennial suspect): a constant-zero additive term someone once meant to make non-zero. Nintendo shipped the hook; thirty years later it became five lemmas in an impossibility proof.
The takeaway. “Machine-checked” means the proof does not contain the sentence “and the other functions obviously don't matter.” It contains, instead, a gayvfj_row for every single one of them. This page is what the smallest of those looks like; the open-surface page (open-hypothesis-surface-2026-06-05.html) counts the ones still to go.
