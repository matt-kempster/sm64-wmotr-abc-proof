no-A ⇒ no-fly

A line-by-line reading of noA_no_spawn_never_flying — every hypothesis, every constituent part — and a straight answer to: have we actually made any progress?

The one-sentence answer. Yes — but the progress is in the endpoints (the step is now the real game code; "flying" is now the real action value), not in the argument. The actual no-A reasoning is still parked entirely inside three assumptions — and the most important one is, as currently written, false for the real game. So the theorem today reads IF (something false) THEN no-fly: a finished scaffold with the main load-bearing beam not yet poured. Details below, with nothing rounded up.

Theorem noA_no_spawn_never_flying : The capstone. Its name is the claim: a no-A, no-spawn-flying run never flies.
forall (init : mem) (is : list Inp) (m : mem), Quantifies over a starting memory init, a list of per-frame inputs is (the run), and an ending memory m.
mem_ok init -> Premise 1. The run starts in a good state: Mario's struct is allocated, his action is non-flying, and his marioObj pointer points off his own block. (Unfolded below.)
noA_run_real is -> Premise 2. Every frame's input has a_pressed = false — no A press, the whole run.
no_spawn_flying_run is -> Premise 3. No frame fires a MARIO_SPAWN_FLYING warp (the Wing-Cap-tower hatch that would set ACT_FLYING with no button). WMotR's object set has none.
reachable mem Inp step init is m -> Premise 4. m is genuinely reached: fold the real per-frame step over the inputs, from init, landing at m.
~ mem_flying m. Conclusion. The final memory is not flying — i.e. the action value loaded from Mario's struct is never ACT_FLYING / ACT_FLYING_TRIPLE_JUMP.
Proof.
intros init is m Hinit HnoA Hnospawn Hreach. Name the four premises.
eapply (noA_run_not_flying mem Inp Hand off to the generic, fully-proved trace harness (§4). It turns "each frame preserves an invariant" + "the invariant excludes flying" into "the run never flies."
(fun i => orb (a_pressed i) (spawn_flying i)) step A frame is "dangerous" if it presses A or spawn-flies; step is the real frame.
mem_flying mem_ok init). "flying" := the real mem_flying; the carried invariant Φ := mem_ok.
- exact Hinit. Base. Φ holds at the start — that's premise 1 verbatim.
- intros i s s' Hd Hphi Hst. Step. Assume a non-dangerous frame from a Φ-state; show Φ survives.
apply orb_false_iff in Hd. destruct Hd as [Ha Hsp]. "Not dangerous" splits into "didn't press A" and "didn't spawn-fly."
eapply frame_preserves_mem_ok; eauto. Discharge with the per-frame lemma (§5) — the one place the real game code enters.
- exact mem_ok_not_flying. Safety. Φ (action non-flying) logically excludes flying. One-line lemma, proved.
- exact (combine_preconditions is HnoA Hnospawn). Fold premises 2 and 3 into the single "no dangerous frame" fact the harness wants.
- exact Hreach. Feed in the run itself (premise 4).
Qed.Closed — given the three hypotheses the Section assumes (§3). That "given" is the whole story.

3. The three hypotheses the whole thing rests on

These are Hypothesis declarations inside the Section (lines 134–146). That placement matters enormously for reading the result honestly — see the box at the end of this section.

Hypothesis reach_value_ok : reach_value_preserves nonflying bm mario_ge. (1) The interprocedural crux. Unfolds to: forall m fd vargs t m' vres, eval_funcall … ge m fd … m' … -> action_sat nonflying m bm -> action_sat nonflying m' bm. I.e. any function reachable in the game preserves "action is non-flying." false as stated set_mario_action with an ACT_FLYING argument is such a function and it does the opposite.
Hypothesis reach_ext_ok : reach_ext_preserves (action_cell bm) mario_ge. (2) Externals. forall ef …, external_call ef ge … m … m' -> Mem.unchanged_on (action_cell bm) m m'. The reached externals are math/runtime builtins, none of which write Mario's action cell. true, unproved
Hypothesis body_preserves_ok : body_preserves_real bm. (3) The body itself. Given (1) and (2), the real exec_stmt of f_execute_mario_action's body carries valid ∧ non-flying ∧ marioObj_wf forward. true, unproved The body has exactly 2 direct stores; both were proved (against the literal AST) to land off the action cell. The remaining work is the structural induction that threads this through the whole body.
Why Print Assumptions looks clean — and why that is misleading. Running the lie-detector on the capstone prints only standard CompCert/Coq axioms (classic, functional_extensionality, external_functions_sem, …) and none of the three residuals. That is not because they're discharged. It's because they're Section hypotheses, so Coq turns them into ordinary premises of the closed theorem term. The honest statement of what we've proved is therefore:
∀ bm Inp a_pressed spawn_flying,   reach_value_ok → reach_ext_ok → body_preserves_ok →   (noA & no-spawn run ⇒ never flying).
The three arrows on the left are the holes. A clean axiom list measures cleanliness, never tethering.

4. The constituent parts, unfolded

Every name the theorem leans on, with its real definition.

mem_flying / mem_nonflying / mem_ok — the state predicates

Definition mem_flying (m:mem) := exists v, Mem.load Mint32 m bm 12 = Some (Vint v) /\ is_flying_int v = true. Real. Load 4 bytes at offset 12 of Mario's block (the action field's true offset, read off the struct layout) and ask whether that integer is a flying constant. No abstract "flying" predicate.
Definition mem_nonflying (m:mem) := action_sat nonflying m bm. Every value the action cell loads satisfies nonflying.
Definition mem_ok (m:mem) := Mem.valid_block m bm /\ mem_nonflying m /\ marioObj_wf m bm. The carried invariant: Mario's block allocated, action non-flying (the goal), and marioObj well-formed (what keeps the body's pointer-chase stores off the action cell).

is_flying_int — what "flying" means numerically

Definition ACT_FLYING := Int.repr 277350553. (* 0x10808899 *) Definition ACT_FLYING_TRIPLE_JUMP := Int.repr 50333844. Definition is_flying_int (n:int) := Int.eq n ACT_FLYING || Int.eq n ACT_FLYING_TRIPLE_JUMP. The two action constants that count as flying, taken from the generated headers. "Flying" is a concrete number test, not a label we invented.

action_sat / action_cell / nonflying — the watched byte

Definition action_cell (bm:block) := fun b o => b = bm /\ 12 <= o < 12 + size_chunk Mint32. The 4-byte region [12,16) of Mario's block — the exact bytes the action lives in.
Definition action_sat (Q:int->Prop) m bm := forall v, Mem.load Mint32 m bm 12 = Some (Vint v) -> Q v. "Whatever the action cell loads, it satisfies Q." The forward value invariant the whole engine threads.
Definition nonflying (v:int) := is_flying_int v = false. Q := "not a flying constant."

step / execute_mario_action_step — the real frame

Definition step (_:Inp) (m m':mem) := execute_mario_action_step m m'. Definition execute_mario_action_step (m m':mem) := exists b_o t res, eval_funcall function_entry2 mario_ge m (Internal mario.f_execute_mario_action) (Vptr b_o Ptrofs.zero :: nil) t m' res. Real. One frame = one CompCert big-step evaluation of the actual generated function f_execute_mario_action (called on an Object pointer; it finds Mario via the gMarioState global internally), over the real Mario genv. The input doesn't branch the relation — preservation holds for any input — which is exactly why the no-A condition must live inside residual (1), not here.

marioObj_wf — the anti-aliasing invariant

Definition marioObj_wf (m:mem) (bm:block) := exists off bobj ofs, field_offset mario_ce _marioObj mario_members = OK (off,Full) /\ Mem.loadv Mptr m (Vptr bm (Ptrofs.repr off)) = Some (Vptr bobj ofs) /\ bobj <> bm /\ (forall gb, find_symbol mario_ge _gMarioState = Some gb -> bobj <> gb). Real. Mario's marioObj field (at its true computed offset) holds a pointer to a block bobj that is distinct from Mario's own block and from the gMarioState block. This is the concrete fact that makes the body's two marioObj->… stores provably miss the action cell. A statement about one field of one struct in real memory — not a forall le.

noA_run_real / no_spawn_flying_run / reachable — the run

Definition noA_run_real is := Forall (fun i => a_pressed i = false) is. Definition no_spawn_flying_run is := Forall (fun i => spawn_flying i = false) is. The two run-level preconditions, as ordinary Forall facts over the frame list. (The input layer — Inp, a_pressed, spawn_flying — is still abstract; grounding it in the real controller word is a separate, orthogonal tethering task.)
Inductive reachable : S -> list Inp -> S -> Prop := | reach_nil : forall s, reachable s [] s | reach_cons : forall i is s s' s'', step i s s' -> reachable s' is s'' -> reachable s (i::is) s''. Fold step over the input list; head = earliest frame. Standard small-step closure.

noA_run_not_flying — the generic harness (fully proved)

Theorem noA_run_not_flying (flying Phi : S->Prop) (init:S) (Hbase : Phi init) (Hstep : forall i s s', a_pressed i = false -> Phi s -> step i s s' -> Phi s') (Hsafe : forall s, Phi s -> ~ flying s) : forall is s, noA_run is -> reachable init is s -> ~ flying s. Pure invariant induction over a trace, no holes. "If Φ holds at start, every no-A frame preserves Φ, and Φ excludes flying, then no reachable state flies." The capstone is just this, instantiated with the real step, the real flying predicate, and Φ := mem_ok.

frame_preserves_mem_ok / execute_mario_action_preserves_real — the bridge

Lemma frame_preserves_mem_ok : forall i m m', a_pressed i = false -> spawn_flying i = false -> mem_ok m -> step i m m' -> mem_ok m'. The per-frame obligation. Proved — by handing off to execute_mario_action_preserves_real, which lifts the body-level preservation through the trivial function entry (the function allocates no stack vars). But that lemma takes the three residuals as arguments — so this proof is real modulo §3.

What genuinely moved. The two endpoints of the theorem are now real SM64 objects: the per-frame step is the actual compiled game function, and "flying" is the actual action value. What did not move — and why "tons of commits" can feel like nothing. The logical heart of the A-Button-Challenge result — "with no A press, no reachable call can ever set the flying action" — is still entirely an assumption (reach_value_ok), and that assumption is currently written in a form that is false for the real game. So as it literally stands today, the capstone is IF (a false thing) THEN no-fly — which says nothing yet about real runs. Until residual (1) is re-stated to use the no-A hypothesis and then discharged, we have a correct, well-built frame around the claim, with the central beam not yet in place. Much of the MarioModel work built real bricks (the value/provenance engine, the store geometry) that feed residual (3), not residual (1) — so they're genuine, but they're not the beam.
The honest headline. We have turned a theorem about a fiction (abstract step, abstract flying) into a theorem about the real program at its endpoints, resting on three precisely-named, individually attackable assumptions instead of one opaque wish. That is real progress and it is the right shape. But we have not yet proved the A-Button-Challenge result, and we are not close on its crux: the one assumption that encodes the actual no-A argument is still open and still mis-stated. Next beam to pour: re-state reach_value_preserves to consume a_pressed = false, then discharge it over the finite real call graph.
