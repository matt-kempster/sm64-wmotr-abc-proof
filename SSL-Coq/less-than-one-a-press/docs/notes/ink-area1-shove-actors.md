# Which SSL Area 1 actors can give the two Ink shoves?

The low setup needs Mario to slide across two different floor-query locations on successive updates. The **first shove**, on spinning-top timer 129, must leave him where the next update will cache the static entrance floor at Y=768. The **final shove**, on timer 130, must move him sideways *after* he has cached 768. His stopped ground step can then save the high stored graphics coordinates (`gfx.pos`, abbreviated G) while his movement and collision positions fall to 768. A useful continuation accepts the warp on 131, captures and retains the top, and reaches Area 2 at approximately (365.593, 5500, −1096.803). The ordinary arrival is (0, 5500, 256). The three grabbable species use the same Mario-side fallback. The game selects the first registered object of each interaction type, so two overlapping grabbables cannot both give this shove in the same pass. A new update rebuilds the collision list. A nonmounting shell, one grabbable and a non-talking Buddy have three different handlers, in that order. Their real hitboxes must overlap Mario's **collision** position when the list is built. Each separation then uses Mario's current **movement** position. The separation is a *target distance between centers*, not the distance Mario travels. The helper wall-corrects the proposed X/Z and checks for a floor there before committing. Mario's earlier cache survives that validation query. **Why the palm tree deserves a separate row.** The outdoor tree is fixed at (−5989, 0, −4850). Its live script gives it a 500-unit hitbox height and calls `bhv_pole_base_loop`. After timer 10 the callback tests a strict vertical band from tree Y−10 to tree Y+530, and checks that the action does not have bit 0x00100000 set. That bit is the on-pole flag when tested against the action word. For a horizontal collision-position offset vector of length d < 70, it adds (70−d)/70 times that vector to Mario's movement X/Z. In real arithmetic the magnitude is d(70−d)/70, peaking at 17.5 when d=35. This helper uses a different formula and timing from the grabbable contact. The POLELIKE list runs before PLAYER, hence before Mario's fresh initial floor lookup. Carry-script freezing stops the tree callback. Both stock X/Z and the vertical band miss the low pyramid setup. **Clone boundary.** Raising an initialized actor changes where Mario can touch it. The experiment must still establish its live interaction type/subtype, dimensions, tangibility, unconsumed status and selection from the collision list. A frozen Goomba keeps its enemy handler; a frozen non-HOLDABLE shell can retain a working shell handler. Freezing a mesh loader or a tree callback affects what it can do on subsequent updates. The small crate, Crazy Box, Buddy and black Bob-omb have the HOLDABLE flag; selecting a used slot for one of these does not itself freeze its native callback. Availability in SSL is an independent question from getting the specific actor to this height, X/Z and phase.
