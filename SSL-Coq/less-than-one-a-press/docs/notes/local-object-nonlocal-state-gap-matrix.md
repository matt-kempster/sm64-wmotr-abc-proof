# Local-Object/nonlocal-State gap mechanism matrix

## Scope and verdict

This note inventories the mechanisms represented or left open in the current
repository by which Mario can acquire, preserve, or use a local raw-Object /
nonlocal-MarioState coordinate split in SSL Area 1 (the exterior, retail Area
1).  It starts at the declared default Area-1 boundary.  The optional castle
prefix is outside this inventory.

The matrix now separates execution models.  Defined valid aliases, same-slot
reuse, known callback retargeting, ordinary scheduler/lifecycle behavior, and
specified external effects remain current Clight mechanisms.  Invalid/OOB
accesses, ACE, post-undefined-behavior continuation, DMA, and interrupts have
no current Clight witness and are deferred to a MIPS/hardware model; this is
not a retail disproof.  See
[the project execution-scope boundary](../compcert-execution-scope.md).

The main conclusion is that the current four-case lineage interface is **not a
globally exhaustive classification of gap mechanisms**.  In
`FourNullSeedLinkedLineageClosures`, the four fields classify only a
*completed final-query lineage* after a caller has already supplied an
`UpperWarpPrecollisionApplyProjection`:

1. the query source is the current collision sample;
2. the selected owner is classified;
3. its identity is canonical; and
4. its geometry is in the modeled stock relation.

`four_null_seed_linked_lineage_closures_rule_out_installer` proves that those
four facts, together with the null default seed, are sufficient to refute a
non-null upper-warp pre-collision apply.  It does not derive the projection
from linked execution, classify how State and Object first diverged, constrain
writers outside the query lineage, or prove that the payload dereferenced at
apply time still belongs to the query owner.  The four cases must therefore
not be described as exhaustive over all retail executions.

The six constructors of `Area1InstallerProjectionEscape` are a broader
scheduler-projection list:

- `EscapePlatformGlobalAliasOrExternalStore`;
- `EscapeFinalQueryOwnerOrSurfaceProjection`;
- `EscapePostQueryObjectCoordinateWriter`;
- `EscapeSkippedQueryCoordinateWriter`;
- `EscapeRetainedEntryOutsideCheckedInboundNodes`; and
- `EscapeUnclassifiedSchedulerShape`.

Even that list is incomplete for the sustained-gap question.  In particular,
it has no explicit constructor for a State-only writer after
`copy_mario_state_to_object`, a coordinate writer anywhere in the interaction
and pre-geometry interval, or a change from the query-owner allocation to the
payload resident at the same raw address when the pointer is later
dereferenced.

The tables below are exhaustive relative to the mechanisms and proof
interfaces currently present in this repository, not a claim that every
possible SM64 memory-corruption technique has been imagined.  Any newly found
defined store should reduce to an Object endpoint, a State endpoint, or an
explicit pointer/lifecycle effect; an unresolved external must be classified
as a protected-cell frame or a concrete writer/lifecycle effect.

`Area1GapApproachCoverage.v` supplies the value-level backbone for that claim.
`trace_ending_in_gap_has_state_object_or_joint_first_creator` exposes a first
divergence on any supplied trace, carries an explicit synchronized-prefix
certificate, and classifies the edge as a State-endpoint, Object-endpoint, or
joint-endpoint change.
`split_to_split_has_one_of_four_persistence_shapes` separately classifies a
supplied split-to-split step as changing neither endpoint, State only, Object
only, or both.  `gap_preserving_trace_has_first_creator_and_classified_suffix`
combines the synchronized prefix and first creator with a classified suffix,
but deliberately requires trace-local evidence that every post-creator edge
preserves the split; the linked run has not supplied that evidence.
`completed_query_different_sample_expands_to_seven_approaches` expands a
supplied different-sample query into pre-geometry State, Graphics retry,
cached-floor snap, post-copy discrepancy, interaction-writer, moving-skip, or
unclassified-projection cases; each of the four schedule cases retains the
equalities tying its query and collision samples to the supplied source and
projection.  Finally,
`precollision_split_expands_to_data_bearing_stage_approach` makes failures of
the terrain frame, platform refinement, and collision frame explicit.  These
are conditional logical classifications; the linked retail step relations and
writer witnesses still have to inhabit them.

### Promise scale

- **High**: a source order or executable abstract witness already exposes the
  right kind of effect, and the missing work is primarily linked reachability
  and memory identity.
- **Medium**: the mechanism is semantically capable but lacks a stock Area-1
  receiver, geometry, timing, or zero-A predecessor.
- **Low**: current arithmetic/source evidence strongly disfavors the route,
  or the mechanism requires corruption for which no concrete retail origin is
  known.

## Why the present four lineage cases are insufficient

The distinction can be stated precisely:

```text
clean linked run
  -> first State/Object divergence
  -> collision caches the local warp interaction
  -> geometry/action phase chooses State or Graphics
  -> State is copied to raw Object
  -> final query stores a platform pointer
  -> frame/area transition preserves that raw address
  -> apply dereferences the currently resident payload
  -> State moves while raw Object remains local
```

`FourNullSeedLinkedLineageClosures` begins near the **final query stores a
platform pointer** step and classifies the query source, owner kind, identity,
and geometry of a supplied projection.  It does not prove any of the arrows
before or after that point.  Consequently:

- a post-copy State-only writer can create the next frame's split without
  changing the raw Object used by the final query;
- an interaction/action-stage helper can change State after geometry but
  before the copy/final query, outside the model's assumed cached-floor
  continuation;
- a raw-Object writer or `gMarioObject` retarget can separate the stored query
  sample from the later collision sample;
- slot reuse or same-epoch payload mutation can make the apply-time bytes
  differ from the query owner's bytes while leaving the query-owner
  classification unchanged; and
- alias/external stores and unclassified scheduler shapes can prevent the
  `UpperWarpPrecollisionApplyProjection` from being constructed at all.

These are not five more mutually exclusive lineage cases.  They occur at
different phases and can combine.  A sound capstone needs a staged product of
classifications, not a flat disjunction about the last query alone.

## Highest-value cross-products

### 1. Different query/current sample -> inactive old top -> JP stale apply

This is the strongest source-and-trace-supported lineage target.  In the
active-frame form, raw Object first caches the upper-warp collision, then a
State/Graphics selection and copy move the final query to a legitimate
top-owned (or other canonical) surface.  The raw pointer then survives the JP
transition.  In the authenticated injected trace, the watched
top is inactive and still free-list depth 47 at the true first destination
apply, with its old payload intact; no same-slot replacement is needed.  The
decisive missing fact is the clean Area-1 query/current sample separation.

### 2. Late State writer -> next-frame State-first query -> JP stale apply

This is a high-priority completeness case but currently a weaker gameplay
candidate:

1. `copy_mario_state_to_object` synchronizes the views;
2. a later object-list callback writes only MarioState;
3. the next collision still samples the old local raw Object and caches the
   upper warp;
4. the subsequent State floor query uses the displaced State and selects a
   dynamic owner;
5. the later copy/final query installs its pointer; and
6. JP retains and applies the raw pointer after the area transition.

The stock SSL-exterior palm is statically tied to `bhvTree`, whose pole-base
callback calls `cur_obj_push_mario_away`; the source attribution of the explicit
grabbing poles to a later packed area subscript is documented but not yet
established by a LevelScript interpretation.  The checked list order places
the tree callback before Mario's PLAYER update and raw Object copy.  The bounded
chronology therefore resynchronizes its X/Z write.
The next useful experiment is narrower: search only post-player lists and copy
escape branches for a live writer.  The other direct caller families found so
far do not supply the necessary upward Y, and no post-copy SSL-exterior caller
is known.  If linked list execution and copy identity close, the concrete
pole/tree branch becomes a normal impossibility lemma.

### 3. Different query/current sample -> same-slot fresh replacement payload

A canonical query can capture a legitimate owner away from the upper warp; a
later raw-Object transport can place collision at the warp; then an unload and
same-slot allocation can make the stale pointer read a different payload.
`lifecycle_counterexample_checked` and
`concrete_area1_fragment_displacement_is_route_sized_3d` show the lifecycle
and displacement stages are semantically capable.
`independent_different_sample_and_fresh_reuse_witnesses_checked` merely places
the schedule and lifecycle witnesses in one conjunction; it deliberately does
not identify their samples, owner, pointer, memory, or timing.  The missing
facts are a coupled linked chronology, sample transport, free-list choice, and
query geometry.  This is therefore a semantic fallback, not the leading
retail lead; the observed inactive-old-top fate is both simpler and better
authenticated.

### 4. Ink Graphics retry -> inactive/freed top -> destination apply

This is the most developed conditional end-to-end shape.  The timer-131
midface arithmetic, non-null retry result, stale pointer milestones, and
destination displacement are checked as fixtures.  The decisive missing
piece is the clean `>=960` Graphics-minus-Object gap plus linked live-surface
and lifecycle execution.

### 5. Interaction interval frame -> likely normal impossibility lemma

The table orders the successful warp before bully, bounce, damage, pole, and
shell handlers, and the handler loop breaks on a nonzero return.  The remaining
wall-check tail sends a local detector array to the wall resolver, while the
disappeared continuation has only the cached-floor Y snap as a known direct
position write.  This makes the once-suggested post-warp X/Z-push plus Y-writer
product a good small **normal-proof** target, not a leading counterexample.
The proof still must execute the indirect handler call and return value, frame
the earlier handlers and helper aliases, and preserve receiver identity; any
failure should carry the concrete writer and coordinate component.

### 6. Canonical owner at query + same-epoch payload mutation

Even perfect owner classification at query time does not freeze the transform
or velocity later read by platform application.  A per-field last-writer
theorem is required in addition to the slot/epoch theorem.  This cross-product
is easy to miss because it satisfies canonical identity throughout.

## Prioritized formal next steps

1. **Add a symmetric endpoint-writer/frame-tail classification.**  Define
   `PostCopyStateCoordinateWriterEscape` and distinguish State writes, raw
   Object writes, Graphics writes, pointer retargets, lifecycle changes, and
   external multi-effects from the return of `copy_mario_state_to_object`
   through the next pre-collision boundary.
2. **Extend interaction selection.**  Replace the two-constructor
   `GeometrySampleChoice` assumption with a linked theorem or an explicit
   `InteractionSelectionCoordinateWriterEscape`; execute handler priority and
   short-circuit behavior.
3. **Construct one data-bearing linked chronology.**  Start with the declared
   default Area-1 memory and make each real frame boundary project to a
   concrete snapshot.  Prove platform-cell and Mario-coordinate block
   identity, rather than using optional or unconstrained projections.
4. **Compose query owner with apply payload.**  Use
   `CachedApplyPayloadFate` after the live surface projection.  For each fate,
   prove exact payload bytes and binary32 displacement or return a concrete
   counterexample trace.
5. **Close the first-divergence theorem.**  From initial State/Object equality,
   locate the first linked step that makes the coordinate loads unequal.
   `defined_store_creating_object_state_gap_targets_one_endpoint` and the
   external-writer refinement give the semantic core; the remaining work is
   reachable-store and receiver provenance.
6. **Test the best counterexample product first.**  Search the bounded linked
   endpoint writers, copy escapes, and scheduler shapes for a concrete
   separation between the upper-warp collision sample and the later final
   query, then couple the installed pointer to the authenticated inactive,
   unreused top through the true first JP destination apply.  Treat fresh
   same-slot replacement as a fallback unless a real allocation trace selects
   it.  This is more informative than expanding the optional castle-to-SSL
   prefix.

If steps 1-5 close without a reachable escape, the existing stock-null,
geometry, writer-bound, and lifecycle theorems can be composed into a normal
impossibility proof.  If one fails, its first concrete store, surface owner,
slot reuse, or scheduler transition is a much stronger counterexample lead
than the present abstract residuals.
