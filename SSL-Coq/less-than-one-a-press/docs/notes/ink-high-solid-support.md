# A high live large box can create the slide and complete Ink

On 2026-11-14, a bounded JP Wafel test found a useful conditional predecessor: Mario starts in **freefall**, presses **B**, and lands against the collision mesh of a supplied high **large breakable box**. The game creates `ACT_DIVE_SLIDE`; a separately placed, non-mounting Koopa shell nudges him on the next update. The chain captures the native spinning top and reaches Area 2 at **(365.5927734375, 5500, -1096.8026123046875)**. The ground slide, low floor cache, graphics split, warp acceptance and spawning displacement are generated by native updates. High airborne Mario, high live box placement and the later shell placement are still supplied. This closes a local execution gap, not the full no-new-A route or object delivery problem.

This is **landing on an actor's solid terrain**, not an enemy hitbox forcing an unsupported ground action. The shell's role is only the later shove. `riddenObj` stays null throughout; `usedObj` visits slots 55, 64 and 156, never shell69. This differs from the existing shell-mount constructor in [high item nudges](ink-high-item-nudge.md). The term stored graphics below means `gfx.pos`, not the rendered model matrix.

## Why the landing retains the useful cache

The source path is `check_kick_or_dive_in_air` (`src/game/mario_actions_airborne.c:108`) → `ACT_DIVE` → `act_dive`'s `AIR_STEP_LANDED` case (`:754`) → `ACT_DIVE_SLIDE`. Starting forward speed32 passes the strict speed28 guard; native dive entry raises speed to47. The recorded event stream executes FREEFALL then DIVE on the first update and changes to DIVE_SLIDE at its end. It does **not** run the slide handler until the next update.

At the start of the first update Mario's X=-1950 is outside the box mesh, so the ordinary floor refresh finds the real static pad at768. The attempted air quarter-step crosses the west box edge and descends into its topY25000. There is no physical ceiling; the query returns the default ceiling height20000. In `perform_air_quarter_step` (`src/game/mario_step.c:431`), `nextY <= floorY` returns LANDED and assigns movementY=floorY even when `ceilingY-floorY <= 160`. That narrow-clearance branch does not commit candidate X/Z or replace the cached floor. Thus Mario lands atY25000, retains X=-1950 and cache768, and enters DIVE_SLIDE natively. This uses the existing source's cancelled-landing behavior; it is not a new global theorem about reachable histories.

The next update refreshes the low pad cache before object interaction. Shell contact pushes Mario toX=-1882. Native `act_dive_slide` reaches `common_slide_action`, whose stopped ground step and floor alignment leave high stored graphics while snapping movement to cached768. The high box is still loaded during that producer update, but it is too far from the now-low collision position to load on the following update. The top's six triangles then load, the low warp is accepted, and the failed-floor retry selects top61. The box remains live, unbroken and at its supplied coordinates throughout Area1; **no support removal is needed**. `load_object_collision_model` (`src/engine/surface_load.c:754`) recomputes distance locally when its stored distance field is19000; that stored field is not a measured persistent distance.

The Crazy Box control reaches `interact_grabbable`'s grab-eligible branch, setting `INPUT_INTERACT_OBJ_GRABBABLE` and ending the interaction pass before the push. Its position is behind Mario, so `mario_check_object_grab` fails the facing guard and actually picks up nothing. Held/used pointers confirm this; the control should not be described as a completed pickup. The native non-mounting shell contact preserves the slide and supplies the shove.

For the explicit clone-state diagnostic, the initial extra writes are `parentObj=gMarioObject`, `curBhvCommand=bhvCarrySomething5`, `bhvStackIndex=0`, matching the existing non-HOLDABLE carry fixture. Native `bhvBreakableBox` is a surface actor with a repeated collision loader (`data/behavior_data.c:1743`); the carry script stops at BREAK (`:3935`) and does not run that loader. Dynamic surfaces are normally cleared each frame. This diagnostic preserves the box's live hitbox/type, yet loses its landing surface. It neither proves the box can be cloned nor rules out every time-stop/stale-surface history. The successful branch requires the **live mesh loader**.

Both large boxes, all three Tox Boxes and the shell-box spawn are present in SSL Area1. This inventory fact does not establish that any can be transported to the supplied high positions. The Tox comparison only rules out the two exact native-phase, XYZ-only placements tested. The high live large box's delivery, high freefall predecessor and appropriately timed shell delivery remain open; the existing low or high frozen hitbox actors cannot simply substitute for a mesh that must be loaded.
